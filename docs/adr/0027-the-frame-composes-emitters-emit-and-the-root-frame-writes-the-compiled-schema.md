# The Frame composes, Emitters emit, and the root Frame writes the Compiled Schema

**An Emitter writes every piece of JavaScript a Schema's checks need, and the Schema's `Frame` (`src/emitters/frame.ts`) only composes those pieces.** The Emitter's hooks hand back the parts: the base check (`_emitBaseCheck`), the pre-modifiers' conditions (`_emitPreModifierConditions`), and what runs once the base check has passed (`_emitTypedChecks`), which comes back as declarations, children's checks, post-modifiers' checks and output statements. `Emitter.emitBody` passes each part to its own setter on the Frame (`setBaseCheck`, `addPreModifierConditions`, `addDeclarations`, `addChildChecks`, `addPostModifierChecks`, `addOutputStatements`). The Frame then puts each part in order and behind the gate the Schema's position needs (the root or nested, a composite or not). `composeChecks()` returns the statements. `composeSchema()` returns them wrapped in the whole `class PvlCompiledSchema<n> extends PvlSchema<…>`, so the root's whole shape lives in one place. The fixed JavaScript fragments the Frame places (`return { issues }` if there are any, the root's returning base check, `return { value }`, and the condition that no child added an Issue) are written in `emitterUtils.ts`, not in the Frame.

This replaces a frame that both placed a Schema's checks and wrote JavaScript of its own (`return { issues };`, `const path1 = …;`, `field0 = output1;`). `_emitTypedChecks` used to return one flat `string[]`, in which the frame couldn't tell children from post-modifiers, so every composite Emitter called the frame's placement helpers itself to put its own gates in the right spot. With named parts, the Frame places every gate, and an Emitter never decides where its post-modifiers run.

A frame created with `compiledSchema` (its class name, line and types) is the root, which replaces the frame's `isRoot` flag. The Emitter still passes `isRoot` to the two methods that write root-or-nested JavaScript, `emitDeclarations` and `emitOutputHandoff`. A frame with no base check set throws on `composeChecks()` and `composeSchema()`, and a nested frame throws on `composeSchema()`. Either throw is a bug in an Emitter, never a user error. Declarations follow one fixed order: the frame's own locals (`path1`, `issueCount1`, written by `Emitter.emitDeclarations`) come first, then the Emitter's.

## Considered options

- **One `frame.emitChecks({ … })` call taking every part at once.** Rejected: a builder throws on a missing base check, and its named slots let the Frame place every gate itself, while a single call grows a parameter for each new part.
- **The root Frame also writes the `new PvlCompiledSchema<n>()` declaration.** Rejected: `Module` swaps that expression in place of the `pvl.compile(...)` call, which already handles a call that isn't a bare `const` initializer.
- **Pre-modifier conditions stay fixed in `Emitter`.** Rejected: new specialised Emitters will add pre-modifiers of their own, so `_emitPreModifierConditions` is an overridable hook. It keeps returning `string[]` until an Emitter needs more.
