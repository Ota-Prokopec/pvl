# Factories take no options

No `pvl.*` factory and no schema constructor takes options, and every type-check message (`'Expected string'`, `'Value matches no union member'`, …) is fixed. A custom `{ message }` (`IssueEditableProps`) exists only on the Modifiers that report an `Issue` of their own: the Constraints (`.min()`, `.max()`, `.length()`, `.int()`), `.refine()` and `object`'s `.strict()`. `.optional()`, `.nullable()`, `.coerce()`, `.passthrough()` and `.transform()` report nothing, so they take nothing.

The alternative given up is a trailing options object on every factory: `pvl.string({ message: 'name must be text' })`, `pvl.object(shape, { message: 'invalid payload' })`, and `pvl.union(members, { message })`, which collapsed a failing union's every member rejection into one `INVALID_UNION` issue with the custom message. It was dropped for three reasons. A type-check failure is the one Issue whose meaning the code already pins exactly (`INVALID_TYPE` on a known path), so a consumer who wants friendlier wording maps it by `code` at the point of display, where the language and tone are known, rather than at every Schema definition. A per-factory message is also one more constructor parameter every schema class must carry and every compiled node must reproduce, for a feature that the Modifier-level messages already cover where wording genuinely varies per call site. And the union collapse discarded exactly the per-member detail [ADR-0012](./0012-composite-schemas-collect-every-issue.md) exists to keep; a failing union now always reports `INVALID_UNION` followed by every member's rejection.
