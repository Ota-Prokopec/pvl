# Compiled Schemas are terminal — no modifier attaches after compilation

`pvl.compile(x)` returns a **Compiled Schema**, a terminal type whose entire surface is `~standard`, `validate()`, `shape` and `element`. None of `@pvl/schema`'s modifiers are on it: `pvl.compile(x).optional()`, `.refine()`, `.transform()`, `.strict()`, `.min()` and every structural edit fail to typecheck. The supported spelling is to apply every modifier first and compile the finished Schema — `pvl.compile(x.optional())` — so there is exactly one correct place to put one. `pvl.compile()` therefore narrows its argument's type rather than returning it, while staying a runtime identity function, so a source file that uses the marker still validates correctly through the interpreted path before the compiler has ever run.

The reason is that a Compiled Schema is emitted code, not a Schema tree. A modifier attached afterwards would have to be honoured by an instruction sequence that was already generated and written to disk, which is impossible without reintroducing the interpreted wrapper that compiling exists to remove. Letting the call typecheck and silently ignoring the modifier is the worst outcome available: the developer's `.refine()` would look attached and never run. Making it a type error means the mistake is found at author time, in the editor, with the fix — move the modifier inside the `compile()` call — immediately obvious.

The restriction is earned only where it applies, so it is scoped tightly. An uncompiled Schema stays fully editable whether it is a primitive or a composite; nothing about `pvl.object({ ... })` changes because `pvl.compile` exists. Reading _into_ a Compiled Schema is also unrestricted: nested composites are reachable through `shape` and `element` without any marking, because the emitted code already had to produce validators for them.

The cost is that the modifier chain and the compile marker cannot be interleaved, so a developer who wants to add a Refinement to an already-compiled Schema has to edit the expression rather than wrap it. That is accepted — it is one edit, made once, at the place the Schema is defined.
