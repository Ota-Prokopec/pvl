# Compiled Schemas conform to StandardSchemaV1

A `Compiled Schema` produced by `packages/compiler` exposes its own conformant `"~standard"` property, making it a drop-in replacement for the `StandardSchemaV1` schema it was compiled from. This was left open in [ADR-0001](./0001-adopt-standard-schema.md) and is now settled: without it, compiling a schema would silently break any consumer that only knows how to accept a Standard Schema (form libraries, API frameworks), undermining the reason `@pcvl/schema` adopted Standard Schema in the first place. A Compiled Schema is a `Schema` subclass instance whose `_checkType` is the fast, non-tree-walking `Instruction` sequence ([ADR-0020](./0020-schema-class-owns-the-pipeline-and-compile-returns-a-plain-schema.md)), so it inherits `"~standard"` from the base class like every other Schema — conformance costs nothing extra. It reports `vendor: "@pcvl/schema"`, not `"@pcvl/compiler"` — see [`docs/specification/standard-schema.md`](../specification/standard-schema.md) for the full conformance rules.

> Amended by [ADR-0029](./0029-a-compiled-schema-is-a-class-expression-implementing-the-schema-type.md): a Compiled Schema writes its own `"~standard"`, implementing the `Schema` type, rather than inheriting it from a base class.
