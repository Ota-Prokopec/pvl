# `enum()` accepts either an `as const` object or a string-literal array

`pvl.enum(source)` accepts two distinct input shapes: this repo's mandated `as const` enum-object pattern (`pvl.enum(SYSTEM_ROLE)`, see [enums-and-constants.md](../specification/enums-and-constants.md)), and a plain array of string literals (`pvl.enum(['A', 'B'])`). Supporting only the `as const` object form would force a consumer with an ad hoc, one-off string set to first invent and export a named enum object purely to satisfy the schema factory; supporting only the array form would leave every already-declared, repo-mandated `as const` enum object needing a duplicated value list just to build a schema from it. Both forms produce the same kind of `EnumSchema`; only the accepted input shape to the factory differs, so this is a widening of the factory's input handling, not two different schema types to maintain.
