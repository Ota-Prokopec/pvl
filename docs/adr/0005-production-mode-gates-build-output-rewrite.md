# Production-mode compilation rewrites build output, never tracked source

`@pvl/schema-compiler` behaves differently depending on `pvlconfig.json`'s `production` flag. When `production: false` (the default, for local dev), it only emits separate generated files — a compiled validator is a standalone export the consuming app can use explicitly, and nothing else changes, so iterating on schemas stays fast and rewrite-free. When `production: true` (intended for CI/build pipelines), it also performs the narrow call-site rewrite from [ADR-0002](./0002-static-ast-compilation-via-ts-morph.md)'s tooling — replacing a `pvl.compile(...)` call with a reference to its compiled output — but only against the app's **build output** (e.g. its `dist/`, or whatever its bundler consumes), never against the tracked `.ts` source files in the repository.

This was chosen over rewriting source directly in production mode: a compiler that can leave a developer's actual repository modified risks generated code getting committed as hand-written, or corrupting uncommitted edits if it runs mid-change. Gating the more invasive rewrite behind an explicit `production` flag, and scoping it to build output only, gets the benefit (a shipped app's imports work with zero manual path changes) without that risk — the source of truth in version control never changes, regardless of mode.
