# `.transform()` and `pvl.compile()` end the Modifier chain

Both `.transform(f)` and `pvl.compile(x)` return a plain `Schema<Input, Output>` rather than a **Chainable Schema**: a Schema whose public surface is `validate()` and `~standard` only. No Modifier, no Constraint and no structural edit is on it, so `pvl.string().transform(f).min(1)`, `pvl.compile(x).optional()` and `pvl.compile(x).strict()` all fail to typecheck. Everything is chained first: `pvl.compile(x.optional())`, `pvl.string().min(1).transform(f)`. A plain Schema can still validate and can still be a field, element or union member of another Schema.

**Naming.** `Schema` is the minimal type and `ChainableSchema` the base class that adds the Modifiers, not the other way round. Every composite types its fields, elements and union members as `Schema`, so the bare word means "any schema" where it is used most. This record originally named the minimal type `ReadOnlySchema` and the class `Schema`, following TypeScript's `ReadonlyArray`/`Array` pattern. That was sound for typing, but it made a union's members read as restricted to read-only schemas when any schema was meant.

**`.transform()`.** A transformed value can be anything, so nothing the Schema knew about its output still holds: a `.min()` after a `.transform()` to a number would be checking a string's Constraint against a number, and `shape`/`element` on a transformed object or array would describe a value that no longer exists. Making `.transform()` end the chain also makes it, always, the last post-modifier, which is what lets [ADR-0010](./0010-modifiers-run-in-chain-order-around-the-type-check.md) run it last and only once nothing has failed. `f`'s parameter is the Schema's current `Output`, `null`/`undefined` included after `.nullable()`/`.optional()`, because `f` really is called with them after a short-circuit. `.refine()`, by contrast, keeps the Schema's class (`RetypedSchema<this, Input, Output>`): a Refinement leaves the value alone. Its predicate is typed with `T | null` after `.nullable()` even though at runtime it never receives `null`; that is wider than needed and harmless.

**`pvl.compile()`.** A Compiled Schema is emitted code. A Modifier attached afterwards would have to be honoured by an instruction sequence already generated and written to disk, which is impossible without reintroducing the interpreted wrapper that compiling exists to remove; letting the call typecheck and silently ignoring the Modifier would be the worst outcome available. So the narrowing happens at the type level, while `pvl.compile()` stays a runtime identity function and an uncompiled source file still validates through the interpreted path. For an **untransformed** `object` or `array`, the result additionally exposes the read-only `shape` (Standalone Keys) or `element`, so nested structure stays reachable. `pvl.compile()` accepts any Schema, primitive or composite, transformed or not; a transformed composite, a primitive or a union compiles to a plain Schema with neither `shape` nor `element`.

**A Compiled Schema is a `ChainableSchema` instance at runtime.** The emitted code builds a subclass of `@pvl/schema`'s `ChainableSchema` whose `_checkType` is the generated code, typed as the plain Schema above. That is what keeps `pvl.object({ a: pvl.compile(...) })` working after compilation: a composite only ever holds `@pvl/schema` Schemas ([ADR-0018](./0018-composite-fields-are-pvl-schemas-only.md)).

The restriction is scoped to where it is earned: an uncompiled, untransformed Schema stays fully editable, primitive or composite. The cost is that the Modifier chain cannot be continued past a Transform or a compile marker, so adding a Refinement to a compiled Schema means editing the expression rather than wrapping it. That is one edit, made once, at the place the Schema is defined.
