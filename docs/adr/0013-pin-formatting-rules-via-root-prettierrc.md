# Pin formatting rules via a root `.prettierrc.json`, not a shared config package

Prettier was already installed as a root devDependency and wired into `pnpm format` / `pnpm format:check`, but with no `.prettierrc` anywhere in the repo, formatting fell back entirely to Prettier's own built-in defaults — undocumented, unpinned, and liable to silently change what "correctly formatted" means the next time Prettier is upgraded. A single root-level `.prettierrc.json` now pins the rules explicitly; the file itself is the source for the values. Two carry a reason worth keeping: `quoteProps: "as-needed"` keeps the plain-identifier keys of `as const` enum objects ([enums-and-constants.md](../specification/enums-and-constants.md)) unquoted, and `proseWrap: "preserve"` keeps the deliberate one-item-per-line structure of docs like `AGENTS.md`/`CONTEXT.md` from being reflowed into paragraphs. Pinning was a deliberate departure from the codebase's prior de facto style, which matched Prettier's built-in defaults only because it was written before any config existed; the codebase was reformatted wholesale in the same change that added the config, so the diff is a one-time, mechanical cost rather than an ongoing source of formatting churn.

The config lives as a single root file rather than a shared `@repo/prettier-config` workspace package. Unlike `@repo/eslint-config` and `@repo/typescript-config`, which individual packages extend via their own per-package config file, Prettier is invoked exactly once, from the root `format` / `format:check` scripts, over the whole tree (`**/*.{ts,tsx,md}`) — there is no second consumer a shared package would serve, so introducing one would add indirection without a corresponding need.
