# Pin formatting rules via a root `.prettierrc.json`, not a shared config package

Prettier was already installed as a root devDependency and wired into `pnpm format` / `pnpm format:check`, but with no `.prettierrc` anywhere in the repo, formatting fell back entirely to Prettier's own built-in defaults — undocumented, unpinned, and liable to silently change what "correctly formatted" means the next time Prettier is upgraded. A single root-level `.prettierrc.json` now pins the rules explicitly: `semi: false`, `singleQuote: true` (with `jsxSingleQuote: false`, so JSX/HTML markup keeps conventional double-quoted attributes once `packages/ui` gets a consumer), `trailingComma: "all"`, `printWidth: 100`, `quoteProps: "as-needed"` (so plain-identifier keys in `as const` enum objects per `docs/specification/enums-and-constants.md` stay unquoted), `proseWrap: "preserve"` (so the deliberate one-item-per-line structure in docs like `AGENTS.md`/`CONTEXT.md` isn't reflowed into paragraphs), and `endOfLine: "lf"`. This is a deliberate departure from both Prettier's own ecosystem-standard defaults (semicolons, double quotes, 80-column width) and the codebase's prior de facto style, which happened to match those defaults only because it was written before any config existed; the codebase was reformatted wholesale in the same change that added the config, so the diff is a one-time, mechanical cost rather than an ongoing source of formatting churn.

The config lives as a single root file rather than a shared `@repo/prettier-config` workspace package. Unlike `@repo/eslint-config` and `@repo/typescript-config`, which individual packages extend via their own per-package config file, Prettier is invoked exactly once, from the root `format` / `format:check` scripts, over the whole tree (`**/*.{ts,tsx,md}`) — there is no second consumer a shared package would serve, so introducing one would add indirection without a corresponding need.
