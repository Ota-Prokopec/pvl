# The compiler emits one Destination File and rewrites nothing

`@pvl/schema-compiler` writes a single **Destination File** — one aggregate module, whatever set of artifacts [ADR-0015](./0015-compiled-schema-destination-resolution.md) emits it as — and never modifies anything that already exists. It does not touch the developer's tracked source, and it does not touch their build output either: adopting a Compiled Schema is a one-line import-path change the developer makes by hand — `from './schemas/user.js'` becomes `from '@pvl/compiled-schemas'` — and that is the only wiring the compiler asks for. There is no `production` flag, and no mode in which call sites are rewritten.

The Destination File is a **complete mirror** of the scanned set, which is what makes that single import swap sufficient. Every export of every file matched by `include` is present in it: Schemas marked with `pvl.compile(...)` as Compiled Schemas, and everything else — unmarked Schemas, helper functions, type aliases, top-level statements — copied through unchanged. A file that matched `include` but contains no marker is mirrored anyway. So the developer never has to track which Schema now lives where, and never ends up importing the same module from two paths.

This supersedes the design this record originally held, which is worth stating because it is the obvious thing to reach for again. That design emitted one generated file per `pvl.compile(...)` call site and gated a call-site rewrite behind a `production: true` flag in `pvlconfig.json`, rewriting the app's build output (never its tracked source) so that a shipped app got compiled validation with no manual import change. Nothing was ever built on it. It is rejected now for three reasons. Rewriting build output means the compiler has to understand the shape of whatever each consumer's bundler emits, which is an open-ended compatibility surface for a feature whose entire benefit is saving one line. It also makes the compiler's behaviour differ between dev and production, so the code a developer tests is not the code that ships — precisely the class of bug an ahead-of-time compiler should not be introducing. And per-call-site output files put the burden of knowing which Schema moved where back onto the developer, which the aggregate Destination File removes outright.

The property the original record was protecting survives intact and is strengthened: the compiler is a pure producer of new files. It never edits an existing one, in source or in build output, in any mode.
