# A Compiled Schema inlines its whole tree into one `_checkType`, written by emitters that mirror `@pcvl/schema`'s methods

**Each Compiled Schema is one class, and its single `_checkType` holds every check of the whole Schema it compiles.** A nested object or array is inlined into its parent's body. The parent never calls a child's `_checkType` or `_validate`, and no private function is emitted per child. The reason is speed: a call per composite costs real time on the hot path, and avoiding that cost is the point of compiling. This supersedes [ADR-0017](./0017-inline-with-delegation-code-generation.md)'s "delegate at composite boundaries", and the matching line of the Standalone Keys spec (#107) that a composite Standalone Key "wraps the private function the parent already calls". A composite Standalone Key gets its own fully inlined class instead, the same way a primitive one already gets its own small function.

The accepted cost is output size. Emitted code grows with the size of the whole tree, and a Schema used in several places is emitted once per place. ADR-0017 named exactly this as the reason to delegate. The size is now traded for speed, and a bundler can still minify the output.

**The emit templates are static methods on one emitter class per schema type, named and parameterised like the `@pcvl/schema` methods they compile.** `StringSchemaEmitter.min({ target, args: [minLength, options] })` writes the check `pvl.string().min(minLength, options)` performs, and `ObjectSchemaEmitter.strict({ target, args: [options] })` writes `.strict(options)`'s. The compiler dispatches a chained method to the emitter method of the same name, so a method with no emitter method isn't compiled yet and is reported as `UNSUPPORTED_SCHEMA`. Each method returns a check (the condition it fails under and its Issue) or JavaScript source text, each written in a `js` tagged template. Three alternatives were rejected: template files with placeholders, a template engine, and AST builders. The first two need a loader, a copy step into `dist` and a placeholder language. AST builders stop the template looking like its output. The emitted-text snapshot and the differential test catch every drift this leaves.

**Default Issue messages exist once, in `@pcvl/schema`.** Each schema file exports an `@internal` `<SCHEMA>_SCHEMA_ISSUE_MESSAGE` object above its class, keyed by method name, with every entry a function (`STRING_SCHEMA_ISSUE_MESSAGE.min(3)`). The schema class calls the entry at runtime. The emitter calls it at compile time and writes the result into the emitted Issue as a literal, so the runtime and codegen halves of a message can't drift. The rest of each check is still written twice, which the differential test covers.

> Superseded in part by [ADR-0028](./0028-emitter-methods-return-source-text-only.md): an emitter method now returns source text only, a check as a whole statement rather than its condition and Issue apart.

> Amended by [ADR-0029](./0029-a-compiled-schema-is-a-class-expression-implementing-the-schema-type.md): the one method holding the checks of the whole tree is now `_validate`, as a Compiled Schema implements the `Schema` type rather than filling `_checkType`.

> Amended by [ADR-0033](./0033-an-emitter-dispatches-chained-methods-through-typed-method-tables.md): a chained method is dispatched through an Emitter's method tables, one per kind of text, each typed by its brand, rather than to a static method found by name. A method no table holds is `UNSUPPORTED_SCHEMA`, and an object's `.strict()` and `.passthrough()` are called by its `_emitSchemaParts` directly.
