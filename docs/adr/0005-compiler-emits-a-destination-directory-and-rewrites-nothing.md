# The compiler emits a Destination Directory and rewrites nothing

`@pvl/schema-compiler` writes one **Destination Directory**, wherever [ADR-0015](./0015-compiled-schema-destination-resolution.md) puts it, and never modifies anything that already exists. It does not touch the developer's tracked source, and it does not touch their build output either. There is no `production` flag, and no mode in which call sites are rewritten.

The Destination Directory is a **complete mirror** of the scanned set, laid out like the application's source root (`rootDir`, default `src`): every file `include` matches becomes a mirrored module at the same path relative to `rootDir`, with or without a `pvl.compile(...)` marker. Marked Schemas become Compiled Schemas, and everything else (unmarked Schemas, helper functions, type aliases, top-level statements) is copied through unchanged. A generated barrel, `index.ts`, re-exports every mirrored module. Because the layout matches the source, adopting the mirror needs no knowledge of which Schema moved where:

- **An alias swap.** The application imports its schemas through an alias and points it at the Destination Directory for production. A tsconfig `paths` fallback overlays the mirror on the source in one line: `"@/*": ["./.pvl/*", "./src/*"]` takes a mirrored module where one exists and falls through to `src` for everything else. A bundler alias does the same. Development keeps the interpreted Schemas, production gets the compiled ones, and the two have the same files at the same paths. No alias can redirect a relative import (`'./schemas/user.js'`), so a schema imported that way can't be swapped.
- **A bundler plugin, later.** A plugin built on [`unplugin`](https://github.com/unjs/unplugin) (one `resolveId` hook that runs under Vite, Rollup, Rolldown, webpack, Rspack, esbuild, Farm and Bun) can redirect the resolution of each scanned file to its mirror, relative imports included, with no alias at all. It changes how imports resolve, not any file, so it keeps this record's guarantee.
- **The barrel, by hand.** `from '<destination>'` imports every mirrored export at once. It exists only in the Destination Directory, so an import of it has no development counterpart unless the application wrote its own `<rootDir>/index.ts`, which is then mirrored as the barrel instead.

## Rejected: one aggregate Destination File

This record first chose a single **Destination File**: every scanned module concatenated into one module under one top-level scope, imported as `@pvl/compiled-schemas`. It is worth stating because one file is the obvious thing to reach for again. Sharing one scope meant the compiler had to rewrite the seams between modules: order them by dependency (so an import cycle became an error), collapse every import into the set into a direct reference, invent names for anonymous default exports, reject namespace imports of scanned files, and rename every private name that clashed with another module's. That was most of the mirror's code, and every rule was a way for the mirrored code to diverge from its source. A folder mirror keeps each module's own scope, so imports between scanned files resolve exactly as they did, and none of those rewrites exist. The one-import swap the single file offered survives as the barrel.

## Rejected: rewriting call sites

Before the single file, this record held a design that emitted one generated file per `pvl.compile(...)` call site and gated a call-site rewrite behind a `production: true` flag in `pvlconfig.json`, rewriting the app's build output (never its tracked source) so that a shipped app got compiled validation with no import change. Nothing was ever built on it. Rewriting build output means the compiler has to understand the shape of whatever each consumer's bundler emits, an open-ended compatibility surface for a feature whose entire benefit is saving one line. It also makes the compiler's behaviour differ between dev and production, so the code a developer tests is not the code that ships — precisely the class of bug an ahead-of-time compiler should not be introducing. And per-call-site output files put the burden of knowing which Schema moved where back onto the developer, which a mirror with the source's own layout removes outright.

The property the original record was protecting survives intact: the compiler is a pure producer of new files. It never edits an existing one, in source or in build output, in any mode; the only thing it ever replaces is a Destination Directory it wrote itself.
