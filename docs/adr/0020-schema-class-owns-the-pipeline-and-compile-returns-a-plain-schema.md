# `Schema` is the base class that owns the pipeline; `pvl.compile()` hands back a plain `Schema`

`@pvl/schema` has two abstract classes, one per file. **`Schema`** (`schemas/schema.ts`) is everything a Schema needs to validate, with no Modifier on it: the pre- and post-modifier arrays and the constructor that seeds them, `validate()`, `"~standard"`, `_validate` with the runners that execute both arrays and read their `MODIFIER_TAG`s, the abstract `_checkType`, and every internal method a Modifier is built with: `_coerceInput`, `_clone`, `_withPreModifier`, `_withPostModifier` and `_withoutModifiers`. **`ChainableSchema`** (`schemas/chainableSchema.ts`) extends it with the five Shared Modifiers and nothing else: `.optional()`, `.nullable()`, `.coerce()`, `.refine()` and `.transform()`. Every concrete schema class extends `ChainableSchema` and builds its Local Modifiers on the inherited `protected` helpers.

The modifier arrays are validation state, not chaining state: `object`'s strip modifier is seeded through the constructor with no chaining, and the tags only mean something to the runner that reads them. So the arrays and the code that runs them live in the same class, which is the one every Schema needs. The internal helpers are on `Schema` too, rather than on `ChainableSchema` next to the Modifiers that call them. That keeps `ChainableSchema` exactly the public chaining surface and nothing else, and leaves the arrays `private` to the class that writes them. The cost is that a Compiled Schema inherits helpers it never calls; they are `protected` and `@internal`, so nothing a consumer sees changes.

`Schema` replaces the earlier `type Schema`. A class can't share its name with a type alias, and a third name for "any schema" would make the vocabulary worse. Because the class has private and protected members, only its own subclasses satisfy it, so a structurally identical object from another library is not a Schema. That is stronger than what [ADR-0018](./0018-composite-fields-are-pvl-schemas-only.md) relied on before, which was `_validate` being required. The catch is that two installed copies of `@pvl/schema` do not accept each other's Schemas. The Destination File already had to import the application's own copy.

**`pvl.compile(x)` returns `Schema<InferInput<x>, InferOutput<x>>`, and the `CompiledSchema` type no longer exists.** At runtime a Compiled Schema is a subclass of `Schema`, not `ChainableSchema`, whose `_checkType` is the emitted code, so its runtime class matches its type and carries no unused Shared Modifier. This supersedes two parts of [ADR-0016](./0016-transform-and-compile-end-the-modifier-chain.md): that a Compiled Schema is a `ChainableSchema` instance, and that a compiled untransformed `object`/`array` still exposes a read-only `shape`/`element`. With `shape` gone, the `.standalone()` marker and the Standalone Key that only existed to populate it go too. A consumer who wants to validate one field on its own keeps a reference to that field's schema.
