# Schema modifiers stored as one ordered step list, not separate refine/transform arrays

`Schema`'s `.refine()` and `.transform()` calls are recorded as a single ordered list of steps (each tagged as either a refinement or a transform), applied in exactly the sequence they were chained, rather than two separate arrays (`_refinements`, `_transforms`) applied refinements-then-transforms. A chain like `.refine(a).transform(b).refine(c)` requires `c` to observe the value _after_ `b`'s transform has run; two separate arrays would silently run both refinements before the transform, changing behavior with no type error or other obvious symptom. This follows from moving modifiers into the base `Schema` class as instance state instead of wrapper classes (ADR-0006): the wrapper-class design preserved call order for free, since each `.refine()`/`.transform()` call wrapped the previous schema — the single-instance design has to preserve that same ordering guarantee deliberately.
