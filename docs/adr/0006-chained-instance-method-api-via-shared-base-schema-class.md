# Chained-instance-method API via a shared base `Schema` class

Every `@pvl/schema` modifier (`.optional()`, `.nullable()`, `.refine()`, `.transform()`, `.coerce()`, and `object`'s `.strict()`/`.passthrough()`) is a method on the schema instance that returns a schema, not a wrapping function or static combinator (`pvl.string().optional()`, never `pvl.optional(pvl.string())`). This matches the Zod-style ergonomics the library is modeled on and lets modifiers compose left-to-right in application order. To implement the common modifiers and Standard Schema conformance exactly once rather than duplicating them across every primitive/composite class, all concrete schema classes (`StringSchema`, `ObjectSchema`, etc.) extend one abstract base `Schema` class that owns `"~standard"` and the common modifier methods; a concrete subclass adds only what's specific to its own shape. The trade-off is a single class hierarchy every schema type must fit into, rather than, say, standalone functions per modifier — judged worth it for the consistency and the one-implementation guarantee for Standard Schema conformance.

## Amendment: one `Modifier` type, and every class keeps its own type

Every Modifier, Shared or Local, the Constraints and `object`'s unknown-key handling included, is a `Modifier` value pushed through the base class's `_withPreModifier`/`_withPostModifier`, which clone the schema (prototype and fields preserved) and append the Modifier to one of its two ordered arrays ([ADR-0010](./0010-modifiers-run-in-chain-order-around-the-type-check.md)). A Modifier whose behaviour departs from the default reading of its result declares that with a `MODIFIER_TAG`, and one that must be replaced rather than stacked (`.strict()` against `.passthrough()`) is removed by the factory that built it through `_withoutModifiers`, so the last one chained wins. There is no per-class check type, no shared Modifier record and no `sharedModifiers.ts`: a Modifier is one method plus one `Modifier` literal, and since every one goes through the same clone, a Modifier chained after another never drops it.

Every class keeps its own type through every Modifier, **primitives included**. A subclass declares a type-only `'~kind'` naming itself re-parameterized with `Input`/`Output`, and the base Modifiers return `Rebind<this, Input, Output>`, so `pvl.string().optional().min(2)` and `pvl.object(shape).nullable().strict()` both typecheck. This reverses the earlier rule that `.optional()`, `.nullable()` and `.coerce()` widened a primitive to the base `Schema` to keep `.min()` off a schema whose accepted types had moved on: with the type check fixed before every Constraint, a Constraint never sees a value of the wrong type, so there is nothing to keep it off. `.transform()` is the one exception: it returns a Read-only Schema ([ADR-0016](./0016-transform-and-compile-return-read-only-schemas.md)).

`CompileCandidate` is any object or array schema, transformed or not, told apart by a type-only `'~compileCandidate'` marker the two classes declare and `.transform()` carries over.
