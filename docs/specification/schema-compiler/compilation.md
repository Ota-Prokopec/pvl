# Compilation

How `@pvl/schema-compiler` finds a schema marked with `pvl.compile(...)` and what it compiles. Read this before you work on discovery, or on which schema a marker compiles. [`schema/compile.md`](../schema/compile.md) defines `pvl.compile()` itself and the runtime shape a Compiled Schema must fill.

## Discovery: static AST analysis, not dynamic import

The compiler never runs or imports the user's schema code. It statically parses the TS/JS source of the files matched by `include` in the user's `pvlconfig.json`, using ts-morph, looking for `pvl.compile(...)` call expressions. See [ADR-0002](../../adr/0002-static-ast-compilation-via-ts-morph.md) for why (never executing user code; the trade-off is that only statically-resolvable schema expressions are compilable, and marking one that isn't is an error rather than a silent fallback).

## What reads statically

A call is recognised when `pvl` is imported from `@pvl/schema` under any name. Its argument may be a `pvl.*` call chain written in place, or a top-level `const` of the same file holding one, followed through any number of `const`s. A name is bound in its scope, as JavaScript binds it, so a parameter or a local that shadows a top-level `const` is not that `const`, and isn't followed (`const MIN = 3; (MIN: number) => pvl.compile(pvl.string().min(MIN))` reads no `3`). This binds names only and checks no type ([ADR-0024](../../adr/0024-the-compiler-checks-syntax-not-types.md)). A method's arguments read statically when they are literals (`3`, `-1`, `10n`, `'a'`, `{ message: 'too short' }`), literals under any number of `!`, `-` and `+` (`!0`, `!!!flag`, `+'2'`, `-+1`), or `const`s holding them, and are then written into the checks as literals. `++`, `--` and other assignments are never read, as they need the variable's runtime state ([ADR-0025](../../adr/0025-static-reading-never-evaluates-an-assignment.md)). A plain `__proto__: …` in an object literal sets the prototype rather than adding a key, so it is no field, while `['__proto__']: …` is one. `pvl.compile()` may wrap any Schema, primitive or composite ([ADR-0016](../../adr/0016-transform-and-compile-end-the-modifier-chain.md)), and what it wraps compiles at the root just as it would nested. Anything else gets an error, and nothing is written. A call that can't be read, or whose result is modified, gets one; a call that reads but isn't a Compilable Schema gets one per problem:

- `COMPILE_ARGUMENT_UNRESOLVABLE`: the argument, or a factory's argument, is imported, built by a function call, spread, held in a `let`, a parameter or a local that shadows a top-level `const`, or an assignment such as `++count`; or a method argument is spread.
- `COMPILE_ARGUMENT_CYCLE`: the argument, or a method argument, follows a `const` that refers back to itself (`const user = pvl.object({ friend: user })`), so reading it would never end. TypeScript reports such a `const` as used before its declaration, but the compiler doesn't type-check ([ADR-0024](../../adr/0024-the-compiler-checks-syntax-not-types.md)).
- `COMPILE_RESULT_MODIFIED`: something other than `.validate()` is read off the result (`pvl.compile(x).optional()`).
- `UNSUPPORTED_SCHEMA`: the Schema uses what isn't compiled yet. Today that is anything beyond primitives, literals, enums and objects and arrays of them, with their Constraints, `.strict()`/`.passthrough()` and `.optional()`/`.nullable()`, at any depth, the wrapped Schema included: a union, `.coerce()`, `.refine()` or `.transform()`.

## Runtime Arguments

A method's argument that doesn't read statically is a Runtime Argument, which the Compiled Schema evaluates: a parameter (the `MIN` above), a `let`, an import, a call, a property read or an operator, `++count` included ([ADR-0030](../../adr/0030-a-method-argument-the-compiler-cant-read-is-a-runtime-argument-evaluated-once-where-it-is-written.md)). Only a spread one has no fixed position to be passed at, so `.max(...limits)` and `{ ...options }` written in place are `COMPILE_ARGUMENT_UNRESOLVABLE`. A factory's argument never is one: it decides the Schema's types or the structure that is inlined, so it must read statically.

Each Runtime Argument is evaluated once, where it is written, as the interpreted path evaluates it. Written inside the `pvl.compile(...)` call, it is passed as written to the Compiled Schema's constructor, which replaces the call ([code-generation.md](./code-generation.md#runtime-arguments-go-through-the-constructor)). Written in a top-level `const` the call follows, it is hoisted into a `const pvlArg<n>` right before that `const`'s declarator, which then reads it, and the call passes that name ([destination-directory.md](./destination-directory.md)). Either way it runs once per evaluation of the code it is written in: `pvl.compile(pvl.string().max(getMax()))` at the top level calls `getMax()` once, and `() => pvl.compile(pvl.string().max(getMax()))` once per call.

## Compilation unit: exactly what `pvl.compile()` wraps

`pvl.compile()` is per-call-site: each call produces its own Compiled Schema for exactly the schema it wraps, whether that's a whole top-level schema (`pvl.compile(pvl.object({...}))`) or one nested field (`pvl.object({ key: pvl.compile(pvl.object({...})) })`). Compiling a nested field does **not** reach up and compile its containing schema — the parent stays an ordinary interpreted `Schema` regardless; if a fully-compiled top-level schema is wanted, wrap the top-level schema itself.

## Modifiers are baked in

Every Modifier is applied **before** compiling and baked into the emitted code, running in the same order and with the same short-circuit and collection rules as the interpreted path ([`schema/pipeline.md`](../schema/pipeline.md), [ADR-0010](../../adr/0010-modifiers-run-in-chain-order-around-the-type-check.md)). Only the _structural_ checks (type guards, required-field checks, array iteration, Constraints) become `Instruction`s. `.refine()` and `.transform()` bodies are arbitrary user code: they will become calls to the user's own functions, imported by reference into the `Destination Directory`, and are never inlined or compiled. Neither compiles yet: today both are `UNSUPPORTED_SCHEMA`, and so is `.coerce()`.
