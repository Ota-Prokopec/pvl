# Code generation

What the code `@pvl/schema-compiler` emits looks like. Read this before you write or change an emit template.

## Everything inlined into one `_checkType`

Straight-line JavaScript: literal `if`/`for` statements, no interpreter loop and no `new Function`. Every check of the whole Schema is inlined into one `_checkType`, nested Schemas included. The parent never calls a child's `_checkType`, for speed. Output therefore grows with the size of the whole tree ([ADR-0023](../../adr/0023-compiled-schemas-inline-nested-schemas-and-mirror-schema-methods.md), superseding [ADR-0017](../../adr/0017-inline-with-delegation-code-generation.md)'s delegation).

A nested object or array is inlined where its parent reads it. Once its type check passes, its checks run in a block of their own, then the output they build replaces the value the parent read (`field0 = output1`), so a nested value is declared with `let`. Its locals are numbered across the whole class (`input1`, `path1`, `field3`, `index2`), and it keeps its own Issue path in one local (`const path1 = [...path, "lines"]`) that its fields' and element's paths extend (`[...path1, index1]`). Without that local, every Issue path would spell out every key above it, and output would grow faster than the Schema with each level of depth. What only runs once every field or element has passed (`.strict()`, an array's Constraints) is guarded by the count of Issues before the node (`if (issues.length === issueCount1)`), because every node pushes onto the one `issues` array.

## Emitters mirror `@pvl/schema`'s methods

The templates live in `src/emitters/`, one class per schema type (`StringSchemaEmitter`, `ObjectSchemaEmitter`, …), with only static methods named like the schema method they compile, plus `_emitBaseCheck({ schema, target, scope })` for the type check, which reads `schema` only when the check needs the factory's argument (`pvl.literal('a')`). Every method of an emitter takes one object, never positional parameters, so a hook or template destructures only what it reads. A template takes `{ target, args }`: `target` is a `CheckingTarget` (the checked value and its full Issue path, as expressions) and `args` the mirrored method's own arguments. It returns source text written in a `js` tagged template ([ADR-0028](../../adr/0028-emitter-methods-return-source-text-only.md)): a pre-modifier's short-circuit condition, as an expression (`field0 === undefined`), or a post-modifier's statement, which for a Constraint is its check, written with `emitCheck({ failsWhen, issue })`. Each kind of text has its own branded string type in `src/types.ts` (`EmittedCheck`, `EmittedShortCircuitCondition`, `EmittedOutputStatement`, …), so one can't be passed where another belongs. Its type is `EmitterMethodOf<…>` of the `@pvl/schema` method it mirrors (`EmitterMethodOf<StringInterpretedSchema['min']>`), so its `args` are that method's own parameters and a change to them fails the compiler's type check. The compiler dispatches a chained method to the emitter method of the same name, so adding a method to an emitter is what makes that method compile.

The emitters extend each other the way the schemas do. The abstract base `Emitter` stands in for `Schema` and does the emitting, following the pipeline of [ADR-0010](../../adr/0010-modifiers-run-in-chain-order-around-the-type-check.md): a Schema's pre-modifiers' short-circuit conditions (`_emitShortCircuitConditions`) guard its base check (`_emitBaseCheck`, the type check), and its post-modifiers' checks (`_emitPostModifierChecks`) run once that has passed. Every method whose name starts with `emit` or `_emit` returns source text, a string or a list of them. A composite's emitter also adds its other parts to the frame (`_addCompositeParts`): its locals (`Emitter.emitDeclarations` writes the frame's own, `path1` and `issueCount1`, which come first), its children's checks, as `_checkType` runs every child, and the statements building its output. Its post-modifiers run only once every child has passed. An emitter whose post-modifiers don't all check its value overrides `_emitPostModifierChecks`, as an object emits only the last `.strict()`, which reads its keys, and one whose schema adds pre-modifiers of its own overrides `_emitShortCircuitConditions`. The calls come from the compiler `Schema`'s two arrays, `preModifierCalls` and `postModifierCalls`: reading a Schema splits its chained methods into them, each in chain order, as `@pvl/schema` adds a Modifier to its pre- or post-modifiers (`PRE_MODIFIER_NAMES`).

Emitters emit, and the Schema's `Frame` (`src/emitters/frame.ts`) only composes what they emit ([ADR-0027](../../adr/0027-the-frame-composes-emitters-emit-and-the-root-frame-writes-the-compiled-schema.md)). `emitSchemaChecks` writes one Schema's checks where its parent reads the value, and `emitCompiledSchema` writes them at the root, as the Compiled Schema's class: both go through `buildFrame`, so any Schema compiles at the root as it does nested. It creates the Schema's frame, a root one when it is handed the Compiled Schema's class name, line and types, passes each part the hooks emit to its own setter (`setBaseCheck`, `addShortCircuitConditions`, `addPostModifierChecks`), lets a composite add the rest (`addDeclarations`, `addChildChecks`, `addOutputStatements`), and adds the output's handoff (`Emitter.emitOutputHandoff`) last among the output statements. `emitSchemaChecks` ends with the frame's `composeChecks()`, and `emitCompiledSchema` with its `composeSchema()`, which wraps the same statements in the class. The frame composes, in order, the declarations, the children's checks, the post-modifiers' checks behind their gate, and the output statements, then wraps them after the base check, then in the pre-modifiers' guard. It places every part where the Schema's position needs it, root or nested, and the fixed fragments `emitterUtils.ts` and `issue.ts` write for it; the only root-or-nested JavaScript an Emitter writes is its frame's locals (`emitDeclarations`, none at the root) and the output's handoff (`emitOutputHandoff`, a return at the root). A failed base check pushes its Issue, and the rest runs in its `else`, at the root as nested, so it reads the value as the type the base check checked. At the root, `return { issues }` follows that `else`, which always returns, so only a failed base check reaches it. A value a pre-modifier accepts skips every check: the root returns it as it is after them (`return { value: value }`), and nested it is left as it is. Post-modifiers run once the base check has passed, or once every child has for a composite; at the root, the Issues collected are returned before the value. Their gate depends on the position: a root composite returns any Issues before and after them, a root primitive after them, a nested composite runs them inside `if (issues.length === issueCount1)`, and a nested primitive writes them as they are, inside its base check's `else`. The output is handed on: the root returns it (`return { value: value }`, or `return { value: output }` for a composite), and nested, a composite puts it back on the value its parent reads (`field0 = output1`) while any other value is left as it is. The frame also names a composite's locals (`input`, `output`, `index`, `element`, `path`, `issueCount`). Only a composite, whose checks build an output, declares locals, numbered from `Scope` when nested, so a primitive's frame numbers nothing and has no locals to read.

A short-circuited root reads like a nested Schema: its pre-modifiers' conditions wrap its checks.

```ts
if (!((value === undefined))) {
  if (typeof value !== "string") {
    issues.push(…);
  } else {
    if (value.length > 2) { issues.push(…); }
    if (issues.length > 0) { return { issues }; }
    return { value: value };
  }
  return { issues };
}
return { value: value };
```

`ChainableSchemaEmitter extends Emitter` adds `.optional()`/`.nullable()` and widens the types for them, and every schema's emitter extends it. A subclass overrides only the `_`-prefixed hooks: `_emitBaseCheck`, `_spellFactoryTypes` when its factory takes an argument (`pvl.literal('a')`) or nests Schemas, and, for a composite, `_addCompositeParts` and `_isComposite`; `_emitPostModifierChecks` is overridden only when a post-modifier doesn't check the value, and `_emitShortCircuitConditions` only to add pre-modifiers. Each hook takes the compiler `Schema` subclass its Emitter compiles (`ObjectSchemaEmitter._addCompositeParts({ schema, frame, scope, isRoot, postModifierChecks }: AddCompositePartsArgs<ObjectSchema>)`), and a nested Schema's Emitter is the one it names (`schema.emitter`). `Scope` (`src/emitters/scope.ts`) carries what one class's emitting shares: the numbering of its locals. Neither a name starting with `_` nor a method the base `Emitter` declares is ever dispatched as a chained method. The compiler's abstract `Schema` (`src/schemas/schema.ts`) reads each factory into its own subclass (`src/schemas/`), which names its Emitter, and reports what can't be compiled yet ([ADR-0026](../../adr/0026-the-compiler-reads-each-factory-into-its-own-schema-subclass.md)).

An emitted Issue's message comes from `@pvl/schema`'s `<SCHEMA>_SCHEMA_ISSUE_MESSAGE`, called at compile time and written as a literal. A message that names a runtime value (`.strict()`'s unknown key) is built at runtime around that message's literal text.

## Each Compiled Schema is a `Schema` subclass

Each `pvl.compile(...)` call becomes, in its mirrored module, a class `PvlCompiledSchema<n>` (counted in source order) placed after the module's imports, and the call becomes `new PvlCompiledSchema<n>()`: the root's frame writes the class, and `Module` writes that declaration in place of the `pvl.compile(...)` expression. The class extends `@pvl/schema`'s `Schema`, imported under an alias so it can't clash with the module's own names, and its `_checkType` is the generated code. Its `Input` and `Output` type arguments are spelled out from the Schema, so it infers the types `pvl.compile()` does. [`schema/compile.md`](../schema/compile.md) holds the contract that class fills: empty modifier arrays, every `Issue` reported at the `path` it is handed, and a typed surface identical to what `pvl.compile()` returns before compilation, so the import swap is a drop-in at the type level too. It inherits `"~standard"` and reports `vendor: "@pvl/schema"` ([`standard-schema.md`](../standard-schema.md#conformance-rules)).

## Issues are literals, so the differential test is load-bearing

Each `Issue` ([ADR-0011](../../adr/0011-result-failure-branch-carries-pvl-issue.md)) is a plain object literal, importing nothing, with its code, message and path written out. Nothing but the differential test against the interpreted path keeps them right, which is why that test is load-bearing, not optional.
