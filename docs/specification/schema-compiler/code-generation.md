# Code generation

What the code `@pvl/schema-compiler` emits looks like. Read this before you write or change an emit template.

## Everything inlined into one `_validate`

Straight-line JavaScript: literal `if`/`for` statements, no interpreter loop and no `new Function`. Every check of the whole Schema is inlined into one `_validate`, nested Schemas included. The parent never calls a child's `_validate`, for speed. Output therefore grows with the size of the whole tree ([ADR-0023](../../adr/0023-compiled-schemas-inline-nested-schemas-and-mirror-schema-methods.md), superseding [ADR-0017](../../adr/0017-inline-with-delegation-code-generation.md)'s delegation).

A nested object or array is inlined where its parent reads it. Once its type check passes, its checks run in a block of their own, then the output they build replaces the value the parent read (`field0 = output1`), so a nested value is declared with `let`. Its locals are numbered across the whole class (`input1`, `path2`, `field3`, `index2`), and it keeps its path in one local (`const path2 = [...path1, "lines"]`) that its fields' and element's paths extend (`[...path2, index2]`). Without that local, every Issue path would spell out every key above it, and output would grow faster than the Schema with each level of depth. What only runs once every field or element has passed (`.strict()`, an array's Constraints) is gated on the count of Issues taken before the node's children (`if (issues.length === issueCountBeforeField0ChildrenValidation)`), because every node pushes onto the one `issues` array.

Every Schema is checked at a target, where its own value is (`CheckingTarget`: the value and its paths, as expressions), and a Composite Schema also has locals, the names it declares to do its work (`CompositeLocalVariableNames`). The two point opposite ways: a target is handed down to a Schema, and a composite builds its children's targets from its own locals. A primitive has a target and no locals, and a nested composite has both, the target its parent built and its own locals. For `pvl.object({ tags: pvl.array(pvl.string()) })`:

```text
The chain for pvl.object({ tags: pvl.array(pvl.string()) }):

object (root)  target: { value: 'value',    path: 'path' }              ← Frame.rootCheckingTarget
               locals: input1, output1, path1, …
  └─ array     target: { value: 'field0',   path: '[...path1, "tags"]' } ← built from the object's locals
               locals: input2, output2, index2, element2, path2, …
       └─ string  target: { value: 'element2', path: '[...path2, index2]' } ← built from the array's locals
                  locals: none
```

## Emitters mirror `@pvl/schema`'s methods

The templates live in `src/emitters/`, one class per schema type (`StringSchemaEmitter`, `ObjectSchemaEmitter`, …), holding one method per schema method it compiles, named like that method and written either in its emitter's module or in `src/emitters/utils/`, as the Shared Modifiers' are in `utils/sharedModifiers.ts`, plus `_emitBaseCheck({ schema, target })` for the type check, which reads `schema` only when the check needs the factory's argument (`pvl.literal('a')`). Every method of an emitter takes one object, never positional parameters, so a hook or template destructures only what it reads. A template takes `{ schema, target, schemaTarget, compositeLocals, args }` and most read only `{ target, args }`. `target` is a `CheckingTarget` (the checked value, its path, and the full Issue path of an Issue about it, as expressions; the two hold the same array except at the root, where an empty path is reported as `undefined`), which for a composite's post-modifier holds its output local as the value. `schemaTarget` is the Schema's own target, and `compositeLocals` its composite's locals, `undefined` for a pre-modifier and for a Schema that isn't a composite. `schema` is the compiler Schema it is chained onto, and `args` the mirrored method's own arguments. It returns its Modifier's step, an object whose one key names the kind of source text it holds, written in a `js` tagged template ([ADR-0028](../../adr/0028-emitter-methods-return-source-text-only.md)), or `undefined` when it writes nothing. A pre-modifier's step is its short-circuit condition, as an expression (`{ shortCircuitCondition: 'field0 === undefined' }`), or its conversion (`{ coercion }`). A post-modifier's is its check (`{ check }`), which for a Constraint is written with `emitCheck({ failsWhen, issue })`, or `.transform()`'s call (`{ transform }`). Each kind of text has its own branded string type in `src/emitters/types/emittedText.ts` (`EmittedCheck`, `EmittedShortCircuitCondition`, `EmittedOutputStatement`, …), so one can't be passed where another belongs, and each is made in one place, by the function in `src/emitters/utils/emittedText.ts` that writes it (`emitCheck`, `emitShortCircuitCondition`, `emitCoercion`, `emitTransform`, `emitOutputStatement`, `emitVariableDeclaration`; an Issue's in `src/issue/utils.ts`), so no other text is cast to one. Its type is `EmitterMethodOf<…>` of the `@pvl/schema` method it mirrors (`EmitterMethodOf<StringInterpretedSchema['min']>`), so its `args` are that method's own parameters, any of them a Runtime Argument, and a change to them fails the compiler's type check. Its further type parameters are the step it writes and the Schema subclass it reads as `schema`, `never` for a method that reads none (`EmitterMethodOf<LiteralInterpretedSchema<PossibleLiteralValue>['coerce'], …, LiteralSchema>`, as a literal converts as its value's primitive). An emitter whose methods take arguments also spells each parameter's type in `parameterTypes`, typed by the same methods (`ParameterTypesOf<StringInterpretedSchema>`), for the constructor a Runtime Argument is passed to. One whose Constraints' default messages name their first argument lists those messages in `argumentMessages`, a constant of `src/emitters/consts/argumentMessages.ts` its checks read too (`STRING_ARGUMENT_MESSAGES`, typed `ArgumentMessagesOf<StringInterpretedSchema>`), which the constructor builds them from. An emitter holds its methods in two tables, split as a Schema splits its calls. Each is spread from the table of the emitter it extends and typed by the step its methods write ([ADR-0033](../../adr/0033-an-emitter-dispatches-chained-methods-through-typed-method-tables.md), [ADR-0040](../../adr/0040-a-chained-method-compiles-exactly-when-its-emitters-pre-or-post-modifier-table-holds-it.md)). `preModifierSteps` holds `.optional()` and `.nullable()`, and a primitive's and a literal's `.coerce()`. `postModifierSteps` holds the post-modifiers: the Constraints, `.refine()` and `.transform()` (`{ ...ChainableSchemaEmitter.postModifierSteps, min, max, length } satisfies PostModifierStepTable`). The compiler dispatches a chained method to the method of its name in the table of its kind (`Object.hasOwn`), so adding a method to a table is what makes that method compile, and `compilesMethod({ name })` reads only the two tables. What a method writes is typed by the table, never cast. A table can be typed by the Schema subclass its emitter compiles (`PostModifierStepTable<ObjectSchema>`), which its methods read as `schema`. An object's `.strict()` reads the keys its shape declares from `schema`, and its `input` and path from `compositeLocals`, as `ObjectInterpretedSchema`'s closes over its shape's keys. `.passthrough()` writes nothing, as it only removes the strip. `_emitCompositeParts` copies the undeclared keys onto the output once either removed the strip (`ObjectSchema.unknownKeysMode`), as `_checkType` does. It skips the copy for a `.strict()` when no other post-modifier reads the output afterwards (`ObjectSchema.readsUnknownKeysAfterStrict`), since nothing can observe the missing keys then ([ADR-0007](../../adr/0007-object-strips-unknown-keys-by-default.md)). A call's arguments are handed on as read from source (`readCallArguments`): the compiler checks syntax, not types ([ADR-0024](../../adr/0024-the-compiler-checks-syntax-not-types.md)), so it trusts them to be what the method's parameters declare.

The emitters extend each other the way the schemas do. The abstract base `Emitter` stands in for `InterpretedSchema` and does the emitting, following the pipeline of [ADR-0010](../../adr/0010-modifiers-run-in-chain-order-around-the-type-check.md): a Schema's pre-modifiers' steps (`emitPreModifierSteps`), in chain order, each a short-circuit condition or `.coerce()`'s conversion, come before its base check (`_emitBaseCheck`, the type check, which every Emitter writes through `emitTypeCheck` from its failing condition and its message). Its post-modifiers' checks (`emitPostModifierSteps`) run once that has passed, and its `.transform()`, which `emitPostModifierSteps` sets apart from them, runs once nothing has failed. Neither dispatching method is a hook, as no emitter overrides it. Every method whose name starts with `emit` or `_emit` returns source text, a string or a list of them, except `_emitSchemaParts`, which returns all of a Schema's parts as one typed `SchemaParts` ([ADR-0032](../../adr/0032-an-emitter-returns-a-schemas-parts-and-the-frame-composes-them-as-a-pure-function.md)). It emits every Schema's parts the same way, and a composite's emitter supplies only its `composite` parts (`_emitCompositeParts`), which it emits first; having them is what makes a Schema a composite. They hold its locals, named by `Scope` before any Schema nested in it, its own declarations, its children's checks, as `_checkType` runs every child, and the statements building its output. Its post-modifiers run only once every child has passed, and read its output local, which `_emitSchemaParts` hands them as their `target`. They are also handed its composite's locals, which a post-modifier that reads something other than the value reads, as an object's `.strict()` reads its keys. `.transform()` writes at `schemaTarget`, as it runs once the output has been handed back onto the value. The calls come from the compiler `Schema`. Its `calls` hold every method chained onto it, in chain order, the `.transform()` that ends its chain included, which `getTransformFunction()` finds by name. `preModifierCalls` and `postModifierCalls` filter them as `@pvl/schema` adds a Modifier to its pre- or post-modifiers (`@pvl/schema`'s `PVL_SCHEMA_PRE_MODIFIER_METHOD_NAMES`). An object's `postModifierCalls` leave out every `.strict()` but one that wins, which happens when it is chained after every `.passthrough()`.

Emitters emit, and the `Frame` (`src/frame/frame.ts`) only composes what they emit ([ADR-0027](../../adr/0027-the-frame-composes-emitters-emit-and-the-root-frame-writes-the-compiled-schema.md)): its static functions take a Schema's parts and the target they were emitted at, and hold no state ([ADR-0032](../../adr/0032-an-emitter-returns-a-schemas-parts-and-the-frame-composes-them-as-a-pure-function.md)). A parent inlines a field's or its element's checks with the child's `emitNestedSchemaChecks`, which emits its parts at the target the parent hands on (`Frame.createNestedCheckingTarget`), declares its value (`let` when its checks replace it, as a composite's output, a conversion or a transform does, `Frame.replacesValue`, else `const`), and inlines `Frame.composeChecks({ target, parts })`. `emitCompiledSchema` emits the root's parts at `Frame.rootCheckingTarget`, `_validate`'s own `value` and `path`, so the root compiles exactly as a nested Schema does ([ADR-0031](../../adr/0031-the-root-schema-compiles-as-a-nested-one-under-one-closing-return.md)). It ends with `Frame.composeSchema(…)`, which is handed the class's name and types, wraps the same checks in the class expression, and closes `_validate` with its one return. For a composite, the frame composes, in order, its path and Issue-count locals, its declarations, its children's checks, its output statements, the post-modifiers' checks behind their gate, which read the output local the statements built (`output1`), as an interpreted post-modifier reads `_checkType`'s output, and the output's handoff, setting the children's checks apart with blank lines when its parts ask for it (`setsChildrenApart`, as an object's fields are), so a blank line is the frame's formatting, never a part; for any other Schema, its post-modifiers' checks. It wraps them after the base check, then places that after the pre-modifiers' parts in chain order: a conversion is a statement before what follows it, and the conditions chained one after another share one guard around it. A Schema with a `.transform()` counts the Issues before all of that (`issueCountBeforeField0Validation`) and then, unless the count changed, replaces its value, after a short-circuit too. A value a conversion or a transform replaces is declared with `let`. It places every part the same way at the root as nested, along with the fragments it writes itself (a composite's path and Issue-count locals, and the output's handoff) and those `issue/utils.ts` writes for it. A failed base check pushes its Issue, and the rest runs in its `else`, so it reads the value as the type the base check checked. The checks never return, at the root as nested, where a return would skip the parent's other fields, and a value a pre-modifier accepts skips every check and is left as it is. Post-modifiers run once the base check has passed, or once every child has for a composite: a composite runs them inside `if (issues.length === issueCountBeforeField0ChildrenValidation)`, and a primitive writes them as they are, inside its base check's `else`. Each reports an Issue about the value itself at its target's `issuePath`, as the base check does. The output is handed on: a composite puts it back on its value (`field0 = output2`, or `value = output1` at the root), and any other value is left as it is. `_validate` then returns `{ issues }` when there are any, and otherwise `{ value }`. `Scope` names a composite's locals (`input`, `output`, `index`, `element`, `path`), numbered at the root as nested (`input1`, `path2`), and they travel in its `composite` parts. Only a composite, whose checks build an output, has locals, so a primitive numbers nothing and has none to read. The Issue counts a Gate compares with aren't among them: the frame names each after the value itself, unique in its class (`issueCountBeforeField0Validation` for a transform's, `issueCountBeforeField0ChildrenValidation` for a composite's post-modifiers'), and declares it when it gates on it. The frame declares the path, which it decides on, when the composite has any checks under its base check, its children's or its post-modifiers'. The path is there to report Issues under the composite, and only a check pushes one: a child's path extends it, and `.strict()` reports an unknown key under it.

A short-circuited root reads like a nested Schema: its pre-modifiers' conditions wrap its checks, and the closing return follows them.

```ts
if (!((value === undefined))) {
  if (typeof value !== "string") {
    issues.push(…);
  } else {
    if (value.length > 2) { issues.push(…); }
  }
}
return issues.length > 0 ? { issues } : { value };
```

`ChainableSchemaEmitter extends Emitter` adds the Shared Modifiers, and every schema's emitter extends it: `.optional()`/`.nullable()`, and `.refine()` and `.transform()`, which call the user's function as a Runtime Argument (`this.arg0.call(undefined, field0 as never)`), the transform's read by `Schema.getTransformFunction()`. It widens the types for them, as the methods chained before a given call left them (`before`): `| undefined`, `| null`, an Input of `unknown` once `.coerce()` is chained, which only a primitive's and a literal's emitter hold, each its own conversion (`src/emitters/utils/coercions.ts`, [ADR-0041](../../adr/0041-coerce-is-a-local-modifier-of-the-primitives-and-literal.md)), and the transform's type parameter as the Output. Each spelled type says whether it admits `undefined` (`SpelledType.undefinedness`), which decides whether an object's key of it is optional. Besides its tables, a subclass writes only the `_`-prefixed hooks. `_emitBaseCheck` is one every schema's emitter writes: TypeScript has no abstract static method, so the type of `Schema.emitter`, `SchemaEmitter`, is the one that requires it, and the base methods that emit a Schema's parts (`_emitSchemaParts`, `emitNestedSchemaChecks`, `emitCompiledSchema`) take `this: SchemaEmitter`. `_spellFactoryTypes` is overridden when its factory takes an argument (`pvl.literal('a')`) or nests Schemas, `_emitCompositeParts` for a composite, `_emitShapeProperty` for an object's Compiled Schema's `shape` and `_emitElementProperty` for an array's `element` ([below](#a-compiled-schema-exposes-its-standalone-keys)), and `_spellParameterTypes` when a parameter is typed by the Schema, as `.refine()`'s predicate takes the value. Each hook takes the compiler `Schema` subclass its Emitter compiles (`ObjectSchemaEmitter._emitCompositeParts({ schema, target, scope }: EmitSchemaPartsArgs<ObjectSchema>)`), and a nested Schema's Emitter is the one it names (`schema.emitter`). `Scope` (`src/emitters/scope.ts`) carries what one class's emitting shares: the numbering of its fields and its composites' locals. Only a method a table holds is ever dispatched as a chained method, so a hook never is, whatever its name, and `compilesMethod({ name })`, which no emitter overrides, says which a Schema can be compiled with. `readSchema` (`src/schemas/readSchema.ts`) reads each factory into its own subclass of the compiler's abstract `Schema` (`src/schemas/schema.ts`), which names its Emitter, and the Schema reports what can't be compiled yet ([ADR-0026](../../adr/0026-the-compiler-reads-each-factory-into-its-own-schema-subclass.md), [ADR-0034](../../adr/0034-every-factory-is-read-through-one-readschema-module-holding-the-factory-to-class-map.md)).

An emitted Issue's message comes from `@pvl/schema`'s `<SCHEMA>_SCHEMA_ISSUE_MESSAGE`, called at compile time and written as a literal. A message that names a runtime value is a template literal around that message's literal text, which writes the value as the interpreted path's own template literal does (`emitMessageAroundValue` in `src/issue/utils.ts`). `.strict()`'s names the unknown key, so it is built as its Issue is; one naming a Runtime Argument is built once, by the constructor (below). Check Options passed as a Runtime Argument are read when the Issue is built, as the interpreted path reads them (`emitConstraintIssue`). An empty custom message falls back through `@pvl/schema`'s `replaceEmptyIssueMessage`, the rule its own `Issue` applies: at compile time for a message written as a literal, and, for one a Runtime Argument decides, as an `||` around the message the check evaluates.

## Each Compiled Schema is a class expression implementing `Schema`

Each `pvl.compile(...)` call is replaced, where it is written, by an instance of a class expression named `PvlCompiledSchema<n>` (counted in source order among the calls `Module` replaces), cast up to the type it implements ([ADR-0029](../../adr/0029-a-compiled-schema-is-a-class-expression-implementing-the-schema-type.md)):

```ts
export const code = (new (class PvlCompiledSchema0 implements PvlSchema<string, string> {
  declare readonly [PVL_SCHEMA_BRAND]: true;
  readonly _standalone: boolean = false;

  get "~standard"(): PvlStandardSchemaProps<string, string> {
    return { version: 1, vendor: "@pvl/schema", types: undefined, validate: (value: unknown) => this.validate(value) };
  }

  validate(value: unknown): PvlResult<string> {
    return this._validate(value, []) as PvlResult<string>;
  }

  _validate(value: unknown, path: ReadonlyArray<PropertyKey>): PvlResult<unknown> {
    const issues: PvlIssue[] = [];
    …
    return issues.length > 0 ? { issues } : { value };
  }

  standalone(): this & PvlStandaloneMarker {
    return Object.assign(Object.create(Object.getPrototypeOf(this) as object) as this, this, { _standalone: true }) as unknown as this & PvlStandaloneMarker;
  }
})() as PvlSchema<string, string>);
```

The root's frame writes that expression, and `Module` writes it in place of the `pvl.compile(...)` expression, each line after the first indented to the line the call is on. A call inside another one's argument is compiled into that one, so only the outermost is replaced. The class implements `@pvl/schema`'s `Schema` type and extends no class: `@pvl/schema`'s `Issue`, `Result`, `Schema`, `SCHEMA_BRAND` and `StandardSchemaProps` come in through one type-only import, aliased so they can't clash with the module's own names. Its name is visible only inside its own body, so it never clashes either. It declares the interface's brand, writes `"~standard"`, reporting `vendor: "@pvl/schema"` ([`standard-schema.md`](../standard-schema.md#conformance-rules)), and `validate`, which calls `_validate` at the root and casts its Result, and its `_validate` is the generated code. It reports whether it is marked `.standalone()` in `_standalone`, declaring the Standalone marker's brand too when it is, and its `standalone()` hands back a copy with the flag set, as `@pvl/schema`'s own does. Its `Input` and `Output` type arguments are spelled out from the Schema, and the cast keeps the call site's type exactly what `pvl.compile()` returns. [`schema/compile.md`](../schema/compile.md) holds the contract that class fills: every `Issue` reported at the `path` it is handed, and a typed surface identical to what `pvl.compile()` returns before compilation, so the import swap is a drop-in at the type level too.

## A Compiled Schema exposes its Standalone Keys

A compiled object writes `shape`, and a compiled array `element` when its element is marked, holding exactly what the interpreted one's type exposes, so the import swap never changes what compiles. A transformed one writes neither, whatever its fields mark, as its type has neither ([ADR-0036](../../adr/0036-standalone-keys-are-reinstated-and-shape-and-element-survive-every-call-but-transform.md)). The parent's own checks are the same whether a key is marked or not: every check is still inlined into its `_validate`.

- **A Standalone Key**, a field marked `.standalone()`, gets a Compiled Schema of its own, a class expression of its own inlining its whole tree, named after its parent's class and its position (`PvlCompiledSchema0_2`), and exposing its own Standalone Keys in turn. The parent's constructor builds each one once, into `shape`, which it declares with its type. Each Runtime Argument is passed on as the parent holds it (`this.arg0`), so it is still evaluated once, where the `pvl.compile(...)` call was. A class exposed this way is generic in nothing, as the root's type parameters are in scope where it is written. An object with no Standalone Key has `readonly shape: {} = {};`.
- **A marked element** gets a Compiled Schema of its own the same way, built into `element`.
- **An unmarked element** is exposed nowhere, as the interpreted array's `element` is `undefined` then: its array writes no `element`, and no class takes anything for it ([ADR-0039](../../adr/0039-an-arrays-element-is-opt-in-as-shapes-keys-are.md)).

`pvl.compile(pvl.array(pvl.string().min(1).standalone()))` compiles to:

```ts
export const tags = (new (class PvlCompiledSchema0 implements PvlSchema<string[], string[]> {
  declare readonly [PVL_SCHEMA_BRAND]: true;
  readonly _standalone: boolean = false;

  readonly element: PvlSchema<string, string> & PvlStandaloneMarker;

  constructor() {
    this.element = (new (class PvlCompiledSchema0_element implements PvlSchema<string, string> { … })() as PvlSchema<string, string> & PvlStandaloneMarker);
  }
  …
})() as PvlSchema<string[], string[]> & { readonly element: PvlSchema<string, string> & PvlStandaloneMarker });
```

The type each one is cast up to is spelled as `pvl.compile()` types it: `PvlSchema<Input, Output>`, with `PvlStandaloneMarker` when it is marked, and `{ readonly shape: { … } }` or `{ readonly element: … }`. Every Compiled Schema's `standalone()` writes the marker, so the type-only import every module gets has it. A module with a marked Compiled Schema imports `STANDALONE_BRAND`, which that one declares, through a second type-only import, so one with none imports nothing unused.

## Runtime Arguments go through the constructor

A Compiled Schema with Runtime Arguments ([compilation.md](./compilation.md#runtime-arguments)) declares a constructor taking each one's value as a `readonly` field, `arg0`, `arg1`, … in the order they are written, and its checks read the field (`this.arg0`). The constructor call passes each one as written, or by the name of the `const` it is hoisted into, so it is evaluated once, where the `pvl.compile(...)` call was, in that call's scope ([ADR-0030](../../adr/0030-a-method-argument-the-compiler-cant-read-is-a-runtime-argument-evaluated-once-where-it-is-written.md)):

```ts
export const getUser = (maxLength: number) => (new (class PvlCompiledSchema0 implements PvlSchema<string, string> {
  declare readonly [PVL_SCHEMA_BRAND]: true;
  readonly _standalone: boolean = false;

  readonly arg0Message: string;

  constructor(readonly arg0: number) {
    this.arg0Message = `String must contain at most ${arg0} character(s)`;
  }
  …
      if (value.length > this.arg0) {
        issues.push({ code: "TOO_BIG", message: this.arg0Message, path: path.length > 0 ? path : undefined });
      }
  …
})(maxLength) as PvlSchema<string, string>);
```

Each parameter is typed from its emitter's `parameterTypes`, or by `_spellParameterTypes` from the Schema, as a function passed to `.refine()` or `.transform()` takes the value as the methods chained before it typed it, so an inline function's parameter is typed as in source. A `.transform()` makes the Compiled Schema generic in its function's return type (`TArg0Output`): it is then built by a generic arrow function taking the Runtime Arguments, from which TypeScript infers it, and whose return type is the upcast, `(<TArg0Output,>(arg0: (value: string) => TArg0Output): PvlSchema<string, TArg0Output> => new (class … )(arg0))((value) => value.length)` ([ADR-0035](../../adr/0035-modifiers-compile-to-calls-to-the-users-own-functions-typed-at-their-place-in-the-chain.md)). A default message naming one, from its emitter's `argumentMessages`, is built once, in the constructor, into a field of its own (`arg0Message`), which the checks read: built on every Issue, it made a failing validation about 40% slower. A field is not `private`, so one a method that compiles to no check takes (`.strict()` before `.passthrough()`), or a default message a custom one replaces, is no unused private member.

## Issues are literals, so the differential test is load-bearing

Each `Issue` ([ADR-0011](../../adr/0011-result-failure-branch-carries-pvl-issue.md)) is a plain object literal, importing nothing, with its code, message and path written out. Nothing but the differential test against the interpreted path keeps them right, which is why that test is load-bearing, not optional.
