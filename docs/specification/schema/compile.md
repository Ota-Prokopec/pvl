# `pvl.compile()` and the compiler-facing surface

Read this before you touch `pvl.compile()`, the `Schema` type, `_validate`, or how a composite calls its children. Everything here must stay aligned with [`@pcvl/compiler`](../../../packages/compiler/AGENTS.md).

`compile()` marks a schema for ahead-of-time compilation, e.g. `pvl.object({ key: pvl.compile(pvl.object({ ... })) })`. It accepts **any schema** — primitive or composite, with any Modifier chained, `.transform()` included — so there is no candidate marker to keep in step with the Modifiers. At runtime, before compilation, it is an identity function — a schema file that uses it but hasn't been through the compiler still validates correctly through the interpreted path.

At the type level it returns a plain `Schema<InferInput<x>, InferOutput<x>>`, plus the argument's `shape` or `element` and its Standalone marker when it has them, and nothing else, each Standalone Key and marked element in them typed as a Compiled Schema in turn, and an array whose element is unmarked having no `element` ([ADR-0039](../../adr/0039-an-arrays-element-is-opt-in-as-shapes-keys-are.md)), so a transformed argument's has neither; there is no `CompiledSchema` type. So `pvl.compile(x).optional()` and `pvl.compile(x).strict()` are compile errors. The supported spelling is `pvl.compile(x.optional())`. `.standalone()` is on the `Schema` type, so it can still be called, and `pvl.compile(x.standalone())` and `pvl.compile(x).standalone()` type alike. A caller who wants to validate one field on its own marks it `.standalone()` and reads it off `shape`, which holds the Standalone Keys only, interpreted and compiled alike ([ADR-0016](../../adr/0016-transform-and-compile-end-the-modifier-chain.md), [ADR-0020](../../adr/0020-schema-class-owns-the-pipeline-and-compile-returns-a-plain-schema.md), [ADR-0036](../../adr/0036-standalone-keys-are-reinstated-and-shape-and-element-survive-every-call-but-transform.md)). At runtime a Compiled Schema is an instance of a class expression that implements the `Schema` type and extends no class, so it is neither an `InterpretedSchema` nor a `ChainableInterpretedSchema`. Its `_validate` is the emitted code ([ADR-0029](../../adr/0029-a-compiled-schema-is-a-class-expression-implementing-the-schema-type.md)). An uncompiled schema stays fully editable.

What keeps that swap working, and must stay aligned with `@pcvl/compiler`:

- **Fields, elements and union members are `@pcvl/schema` Schemas only**, typed as the `Schema` type so a transformed or compiled child fits, and called through their own `_validate` with the parent's path extended. A Standard Schema from another library is rejected at the type level: it lacks the `SCHEMA_BRAND` key the type requires, which `InterpretedSchema` and each Compiled Schema `declare` ([ADR-0018](../../adr/0018-composite-fields-are-pvl-schemas-only.md), [ADR-0029](../../adr/0029-a-compiled-schema-is-a-class-expression-implementing-the-schema-type.md)).
- **The `Schema` interface is the whole contract a Compiled Schema fills.** It writes the brand, `"~standard"` and `validate(value)`, which calls `_validate(value, [])`, and its `_validate(value, path)` holds the checks of the whole tree, nested Schemas inlined rather than called ([ADR-0023](../../adr/0023-compiled-schemas-inline-nested-schemas-and-mirror-schema-methods.md)). It also writes `_standalone`, the flag an object reads to keep a field in its runtime `shape`, and `.standalone()`, which hands back a copy with the flag set ([ADR-0036](../../adr/0036-standalone-keys-are-reinstated-and-shape-and-element-survive-every-call-but-transform.md)). A compiled object writes its `shape`, and a compiled array its `element` when the element is marked, holding what the interpreted one holds. Every Modifier is baked into those checks, so no pipeline runs around them. `_validate` must report every `Issue` at the `path` it is handed. It returns `Result<unknown>`, as the emitted checks build values TypeScript can't follow back to `Output`, and `validate` casts that Result. The emitted class declares `implements Schema<Input, Output>`, so a change to that type in `@pcvl/schema` fails the typecheck of every Destination Directory.
- **Default Issue messages are shared.** Each schema file exports an `@internal` `<SCHEMA>_SCHEMA_ISSUE_MESSAGE` object, one function per method, which the schema class calls at runtime and the compiler calls to write each message as a literal. So is the rule for an empty custom message, `issue.ts`'s `@internal` `replaceEmptyIssueMessage`, which `Issue`'s constructor and the compiler both call.

See [`compiler/compilation.md`](../compiler/compilation.md) for what the compiler does with a marked schema.
